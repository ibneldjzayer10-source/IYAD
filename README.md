# IYAD — بوت ريلز BMW (IYAD)

نظام يبني **ريلز إنستغرام عمودية (9:16)** بمحتوى BMW بالعربية (تعليق صوتي + ترجمة +اقتطاع ذكي) وينشرها تلقائياً **3 مرات يومياً** عبر Zernio/Late API — بمحتوى خام من Google Drive وسكربتات من `topics.txt`.

> ⚠️ هذا مستودع فيه **نشر آلي حقيقي** لحساب إنستغرام. جرّب دائماً بـ `dry_run` قبل أي نشر فعلي.

## مكونات المستودع

| المسار | الدور |
|--------|-------|
| `.github/workflows/main.yml` | المجدول (cron `0 11,16,20 * * *` UTC) + زر يدوي مع خيار `dry_run` |
| `scripts/publish_reel.py` | كود النشر الكامل (استُخرج من الـworkflow ليُختبر ويُعدَّل محلياً) |
| `topics.txt` | محتوى النصوص: **107 سطر** بصيغة `نص التعليق \| الوصف \| الوسوم` |
| `bmw-empire/bmw-empire/run_pipeline.py` | مشغّل خط الأنابيب المحلي (19 خطوة) |
| `bmw-empire/bmw-empire/commands/` | 20 ملف مهارة (كل ملف = شرح + كتلة Python تُنفَّذ) |
| `bmw-empire/bmw-empire/common.py` | أدوات مشتركة (تحميل/حفظ JSON، ffmpeg، فحص الحقوق) |
| `tests/` | اختبارات آلية بلا مكتبات خارجية |
| `.env.example` | كل متغيرات البيئة المدعومة (انسخها إلى `.env`) |

## النشر الآلي (GitHub Actions)

1. **السر المطلوب:** `ZERNIO_KEY` في *Settings → Secrets and variables → Actions*.
2. **الجدول:** 3 مرات يومياً (11:00 و16:00 و20:00 بتوقيت UTC).
3. **تجربة بدون نشر:** *Actions → BMW Auto → Run workflow → فعّل `dry_run`* — يبني الفيديو ويطبع الوصف ثم يتوقف.
4. **ضمانات السلامة:**
   - `concurrency` يمنع تشغيلين متزامنين (ننشر مكرر).
   - يتجاوز النشر إذا كان **نفس الوصف منشوراً مسبقاً** (`[skip]` في السجل).
   - أي رد API بخطأ (≥300) يوقف التشغيل بفشل حقيقي — لا «نجاح» كاذب.
   - سجلات واضحة: `[topic]` و`[videos]` و`[rights]` و`[ok]`.
   - عند أي فشل يُفتح issue تلقائياً في المستودع (أو تعليق في issue المفتوح) — لا يمر فشل بصمت.
5. **الساعات:** `timeout-minutes: 20` فلا يعلق تشغيل طويلاً.

## صيغة `topics.txt`

سطر واحد لكل ريل، ثلاثة أقسام مفصولة بـ `|` **بلا أقسام فارغة** (يتحقق منه الاختبار `tests/`):

```
نص التعليق الصوتي... | وصف إنستغرام مع وسومه | m5,f90,g90
```

## التشغيل المحلي

```bash
cd bmw-empire/bmw-empire
# لينكس/ماك:
pip install -r requirements.txt   # + ffmpeg مثبت على النظام
# ويندوز: شغّل start.bat (أو النسخة النصية start.bat.txt قبل التسمية)
python run_pipeline.py --dry-run           # تجربة بلا نشر
python run_pipeline.py --only 5 6          # خطوات محددة
python run_pipeline.py --skip-publish      # كل شيء عدا النشر
```

المتغيرات: انسخ `.env.example` ← `.env` وعبّئها (详见 الجدول داخله).

## الاختبارات

```bash
python3 -m unittest discover -s tests -v
```

بلا أي مكتبات خارجية، ويفحص: صيغة كل سطر في `topics.txt` · صحة استخراج كتل Python من المهام الـ20 · صحة سكربت النشر ووجود ضماناته · بنية ملف الـworkflow. يُشغَّل آلياً على كل push/PR عبر `.github/workflows/test.yml`.

## قواعد المحتوى والحقوق

- لا يُرفع ولا يُنشر إلا محتوى برخصة Creative Commons أو مصدر وافقت عليه في `approved_urls.txt`.
- كل ريل: تعليق صوتي أصلي + معلومات تقنية، مع ذكر المصدر عند الحاجة.
- أرقام المحركات في الخطوة 06 تقريبية — راجعها قبل النشر.
- ✅ **فحص الحقوق موصول الآن:** سكربت النشر يطبع `[rights]` لكل مقطع، و`RIGHTS_ENFORCE=1` يمنع غير المعتمد (الافتراضي `0` = تحذير فقط لا يوقف النشر).

## ملاحظات

- `start.bat` (سابقاً `start.bat.txt`) يعمل مباشرة بالنقر المزدوج.
- لا يوجد `LICENSE` بعد — أضِف رخصة من *Settings → Add file → Choose a license* إن أردت نشر المستودع كقالب.
- متطلبات التشغيل الآلي مثبتة بإصدارات ثابتة داخل `main.yml` (حدِّثها معاً عند الترقية).
